# User interviews

1. **Goal.** Name the open questions the conversations must answer, and which plan decisions depend on them.
2. **Whom.** Three to five people from different segments: a beginner, an experienced user, a small and a large customer, users of each main competitor.
3. **Questions.** Start from the set in `docs/DISCOVERY.md`. Add one question per bet in the plan, about the last time they did that task. Write them in the language of the conversation, each with what it decides. Mark the core questions for a short call.
4. **Rules for the interviewer.** Do not describe the product until the last question. Ask about the past, not about opinions. Ask what they pay now. Get consent before recording, say that AI will process it, and ask for client data to be hidden.
5. **Notes.** One row per conversation, with no names or contacts: role, organization size, current tool and cost, pains named unprompted, workarounds paid for, willingness to try.
6. **Score.** A pain counts when at least two of five name it on their own and already pay or lose time over it. Compare the result with the stop rule agreed in advance.
7. **Report** to the owner: what passed, what did not, and the recommended next step, including stopping.
