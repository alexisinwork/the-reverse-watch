# The Reserve — руководство по использованию базы

## Назначение

The Reserve — русскоязычная база знаний по 200 часовым брендам для рекомендательного движка. Срез данных: 28 августа 2026 года. База предназначена для локального RAG-контура, в том числе для интеграции с Mastra и моделями через Ollama.

## Состав

- 200 брендовых файлов `.md` — по одному файлу на бренд.
- `_INDEX.md` и `_INDEX.csv` — кросс-брендовый индекс референсов с нормализованными полями для фильтрации и аналитики.
- `_SCHEMA.md` — структура брендового файла, словарь полей и правила нормализации.
- `_QUESTIONNAIRE.md` — вопросы Q1–Q16 и варианты ответов рекомендательного сценария.
- `_ROADMAP.md` — полный охват позиций 1–200 и соответствие позиций файлам.
- `_build/` — служебные скрипты и отчёты сборки. Каталог `_build/` в RAG-индексацию не включать.

## Структура брендового файла

Каждый брендовый файл содержит семь разделов:

1. **Юридическая и корпоративная анатомия.** Владелец, юридическая и производственная преемственность, фактический выпуск, происхождение компонентов и существенные ограничения по интеллектуальной собственности.
2. **Психологический код и социальный сигнал.** Невербальный сигнал, архетипы, типовые причины сожаления после покупки и пользовательская мотивация.
3. **Каталог референсов.** Модели, размеры, калибры, запас хода, частота, водозащита, цена и ценовой тир, посадка, рыночный импульс, статус, вторичная стоимость, ликвидность и риск хайпа.
4. **Рыночный слой и профиль покупателя.** Бюджетные слои, типовые сценарии владения и ограничения применимости.
5. **Маппинг на опросник Q1–Q16.** Соответствие параметров бренда и референсов ответам пользователя.
6. **Векторные теги.** Валидный JSON с нормализованными признаками бренда и блоком `data_confidence`.
7. **Источники.** URL и ограничения интерпретации данных.

## Словарь значений

### `price_tier`

Допустимые значения:

- `under_300`
- `300_500`
- `500_1k`
- `1k_2k`
- `2k_5k`
- `5k_10k`
- `10k_15k`
- `15k_plus`

### `market_momentum`

Допустимые значения:

- `evergreen`
- `macro_trend`
- `insider_hype`
- `speculative_bubble`
- `contrarian`

### `production_status`

Допустимые значения:

- `active` — текущий выпуск с возможностью покупки новым;
- `vintage_only` — современного выпуска нет;
- `nos_stock` — производство остановлено, доступны складские остатки, NOS или пересборки;
- `waitlist` — выпуск продолжается, практический доступ ограничен листом ожидания или аукционом;
- `revived` — выпуск возобновлён после производственного или юридического разрыва.

### Маркеры достоверности

- `[набл.]` — наблюдаемое значение, подтверждённое источником.
- `[оц.класс]` — классовая оценка; основание оценки указывается в маркере или рядом.
- `[нет данных]` — значение установить нельзя; причина указывается в маркере или рядом.

### `data_confidence`

Объект `data_confidence` находится в JSON раздела 6 и содержит поля:

- `dimensions` — достоверность размеров;
- `market_data` — достоверность рыночных данных;
- `service_data` — достоверность сервисных данных;
- `notes` — пояснение состава наблюдаемых, оценочных и отсутствующих данных.

Для первых трёх полей допустимы `observed`, `estimated_class` и `missing`.

## Рекомендации по чанковованию для RAG

1. Основная граница чанка — раздел H2. Не объединять разные нумерованные разделы в один чанк.
2. Таблицу каталога не разрывать посередине строки. Заголовок таблицы добавлять к каждому каталожному чанку.
3. JSON раздела 6 хранить отдельным чанком метаданных. Использовать его для структурной фильтрации и ранжирования, а не для семантического поиска.
4. Раздел 3 резать по одному референсу на чанк. К строке референса добавлять заголовок таблицы и краткий контекст статуса каталога.
5. В метаданные каждого чанка передавать:
   - `brand`;
   - `brand_rank`;
   - `source_file`;
   - `price_tier`;
   - `production_status`.
6. Для некаталожных чанков с несколькими ценовыми тирами `price_tier` хранить как массив. Для каталожного чанка использовать тир конкретного референса.
7. `_build/`, служебные отчёты и промежуточные данные в embedding-индекс не включать.

## Правила фильтрации для рекомендательного движка

1. Записи с `data_confidence=estimated_class` не отбрасывать. Понижать их вес при ранжировании и явно помечать в пользовательской выдаче как оценочные.
2. При запросе «купить новыми» исключать `production_status=vintage_only` и `production_status=nos_stock`.
3. `production_status=waitlist` разрешать в выдаче только с предупреждением о сроке ожидания и необходимости подтвердить доступность.
4. Значение `не применимо` в L2L или диапазоне обхвата запястья означает, что предмет не является наручными часами. Такие записи исключать из подбора наручных часов; числовое значение вместо `не применимо` не выводить и не вычислять.
5. Брендовый `production_status` не заменяет статус конкретного референса. Для смешанных каталогов сначала применять статус строки, затем статус бренда.

## Ограничения

- Данные вторичного рынка привязаны к срезу 28 августа 2026 года. Перед расчётом текущей цены, ликвидности или премии их необходимо обновлять.
- Часть размеров, стоимости сервиса, вторичной стоимости и диапазонов посадки является классовой оценкой.
- Для марок с прерванной юридической или производственной линией винтажный рынок и современный выпуск разделены. Современный статус товарного знака нельзя переносить на исторические референсы.
- Цена предложения не равна цене закрытой сделки. Процент вторичной стоимости не является прогнозом доходности.
- Наличие страницы модели или статуса `active` не гарантирует складское наличие.
